# Lumiverse Desk Companion

A Spindle companion that puts a chosen character beside your desktop. Choose a screen source in Lumiverse Desktop and optionally remember its approval. Then share a screenshot or short clip with one widget action, receive a brief reaction in the character's own voice, and optionally hear it through a configured TTS connection. Add a question when you want to steer the conversation.

## Build and check

Requires Bun 1.4.2+ and the published `lumiverse-spindle-types@0.6.71` package. There are no local SDK paths or runtime dependencies.

```sh
bun install --frozen-lockfile
bun run check
```

The build emits `dist/backend.js`, `dist/frontend.js`, and a minified `dist/widget.js`. The native widget entry intentionally excludes the main drawer/onboarding code. `bun test` tests the actual worker controller with a mock host, input validation, source isolation, cancellation, capture release, bounds, voice recording, STT/TTS adapters, and widget interactions in jsdom. It does not capture your screen, access a real microphone, or call a paid provider. jsdom is development-only and is not bundled into the extension.

## Install and try it

1. Use the Lumiverse/backend and Desktop builds containing the capture integration. The manifest's version floor is 1.2.5, but the exact release number alone is insufficient: the widget checks `frontend-session-origin-v1` and `ctx.frontendSessionId` on the frontend; the worker separately checks `desktop-capture-worker-v1` and `frontend-session-routing-v1` on the backend. The server-routing capability is not a frontend capability and must not gate widget creation.
2. Install from this repository through Lumiverse's Extensions panel. The host can build the sources, or you can ship the generated `dist/` bundles.
3. Enable the extension and grant `ui_panels`, `characters`, `generation`, and the desired `screen_capture`/`screen_recording` permissions. Grant `media` for optional STT and TTS. Capture grants require administrator/owner approval; they never replace native consent. If the widget is not visible, open the **Desk Companion** drawer tab and press **Open widget**.
4. Use **Set Up Screen Capture** in the extension's permissions area, or **Browser → Enable Extension Screen Capture…** in the desktop tray. Sign in through native OAuth for the same account that owns the model connection. Desktop remembers transport setup and reconnects for that instance; a browser cookie alone does not enable capture.
5. Configure an image-capable model connection and an optional TTS connection in Lumiverse's normal Connection/Voice settings. The demo stores no API keys and creates no connections.
6. In the **Desk Companion → Companion** tab, choose a character, model connection, and desktop. Leave the question blank for a natural reaction, or add a direction. Wait for **Saved**, then click **Look at my screen** in the widget. On first use, Desktop names the extension and destination and lets you choose a source. Enable **Remember this source and approval for this extension** for later matching requests to go straight to capture. **Review Before Sending** is optional; selecting a source authorizes this capture and send without a mandatory second Share click.
7. For video, select **Video clip**, 1–30 seconds, a video-capable desktop, and a Gemini connection (`google`, or a Gemini route through `google_vertex`). Provider hints are not proof that an arbitrary model supports media. The host and model still enforce actual support. Windows encoding is hardware-preferred; macOS is hardware-required.
8. To use a system floating pop-out, use the host's widget pop-out control or Desktop's **Floating Widgets** tray menu. The host loads `setupWidget(ctx, target)` from `dist/widget.js`; the extension registers the same single widget at index 0. No `window.open` or Tauri IPC is used.
9. In the **Speech** tab, choose a voice connection under **Spoken replies**. **Use character's voice** selects an accessible connection referenced by `character.extensions.ttsVoice`. Spindle speaks with that connection's default voice and the host's Voice & Speech playback settings; extension-specific voice/speed overrides are not supported by this API. Enable TTS in Lumiverse's Voice & Speech settings. Enable the **Spoken replies** switch, or leave it off and use **Speak reply** manually. Playback and audio controls belong to Lumiverse.
10. In **Speech**, optionally enable **Voice input**, select **Whistle (on this device)**, **STT connection**, or **Web Speech** when available, and speak naturally. Whistle needs no saved connection; the connection provider requires an accessible STT profile. The same main action starts `ctx.stt.start({ continuous: false })`. Spindle finishes after confirmed speech followed by silence, returns the final transcript, and the extension combines it with any typed direction before requesting screen capture. Cancel discards the input; there is no fixed listening duration. No separate Record, Transcribe, Generate, or Speak buttons are required for the configured sequence.
11. In **Shortcuts**, bind **Share screen** to run that configured workflow, or **Share without voice input** to skip the microphone for one request. The embedded host controls offer focused and global bindings; global mode requires Desktop's native opt-in. No default shortcut is installed. These actions also appear in the command palette and Desktop **Settings → Key Bindings**.

The shared character picker shows thumbnails, searches the full library, and loads 50 more characters as you scroll. The selected character remains available while browsing or searching. Hosts without shared-select pagination preload the remaining pages for their local dropdown. Up to 200 model connections and the first 100 TTS connections are displayed. Preferences persist in the extension's per-user `companion-settings.json`, isolated even for operator-scoped installations. Replies and live workflow/speech state stay in worker memory: a reopened widget receives the latest state, but restarting the worker clears replies. No capture, transcript, or audio is persisted. Both speech options default off on first use; saved opt-ins start only after a share click or configured command/shortcut.

## Sidebar and widget synchronization

All configuration lives in the **Desk Companion** sidebar, organized into **Companion**, **Speech**, and **Shortcuts** tabs. The form uses Spindle's shared selects, switches, numeric input, text area, status badges, and collapsible help. These controls inherit Lumiverse's active theme; older hosts retain native form controls. The floating widget contains the share action, reply, and Settings shortcut. Cancel, speech playback controls, and Clear appear when relevant. Configuration summaries and execution-flow reminders are omitted. Its root has an explicit bounded height, and its content scrolls when the viewport is small. For a native pop-out, Settings activates a registered sidebar in a connected main document; bring the main Lumiverse window forward if needed.

The worker owns settings revisions and broadcasts configuration, streamed replies, busy/cancel state, and speech status only to subscribed documents for the authenticated account. Different accounts never share that state. A share first claims the current configuration revision, so stale widgets cannot silently act on newer settings and multiple widgets cannot start competing microphone/capture workflows. Configuration is frozen while a share runs. Saving settings or reopening a widget never triggers capture, generation, STT, or TTS. Audio plays only in its originating widget; another synchronized widget can Stop speech or cancel the workflow without re-synthesizing the reply. Closing a subscribing document removes its subscription; closing the owner cancels its in-flight work.

Companion views discover connected desktops and advisory approval status on startup, when the window regains focus or visibility, and through **Refresh** or **Check desktops**. There is no periodic connection or discovery polling. Subscriptions recover on Spindle's authenticated `CONNECTED` event, page restoration, or a failed settings save; ordinary focus changes keep the existing subscription and controls. Discovery never captures or calls a model or speech provider. The widget shows setup guidance when attention is needed, with a **Check desktops** recovery action; normal approval/readiness information stays in settings. A saved desktop that disconnects stays selected as unavailable. Updated clients retain a stable ID across reconnects and restarts, so that same device becomes ready on the next discovery without reselecting it. Older clients can receive a new registration ID, which must be selected explicitly even if its name matches. Another device is never substituted for a saved target. Approval discovery reports remembered/required/paused approval and missing sources or OS permission, without exposing source identities. It is advisory: capture always rechecks actual native approval.

Shortcuts require a backend advertising `command-session-routing-v1`, which supplies authenticated account/document origin as the optional third `commands.onInvoked` callback argument. The matching host change is included in the backend workspace. The command selects exactly one companion view in that document; an in-document widget takes priority, with the sidebar as fallback when a widget has been popped out. Microphone and speech run in the invoking document, while replies and cancellation synchronize with its account's other widgets. Missing configuration, busy state, or cooldown cannot queue a later capture. Older hosts keep button sharing available and show update guidance instead of registering unsafe shortcuts.

Keep Desktop's integrated browser open and signed in. Global bindings may work while its window is hidden or in the background; closing the browser, signing out, or disabling the extension stops delivery. The shortcut uses the saved capture device, kind, model, and written direction. The normal action includes STT only when enabled in **Speech**; the quick action leaves that preference intact and still honors automatic reply speech. First-use native capture and microphone permission prompts still apply. Binding storage and conflicts are managed by Desktop, scoped to the installation, instance, account, and extension.

## Default companion voice

The default prompt asks for a spontaneous, in-character reaction to one or two things that stand out, rather than a screen inventory or unsolicited advice. Responses normally target 1–3 short sentences (20–60 words), with more detail only when requested. The character's name, description/background, personality, scenario, greeting, dialogue examples, and portrayal instructions shape phrasing, rhythm, humor, and emotional tone; the prompt does not force a generic cheerful assistant voice. These are model instructions, not a guaranteed word-count limit.

An optional question overrides the default reaction request without removing the character context. For video-capable routes, the character is prompted to consider visible motion and changes across the approved clip. They are not told they have continuous live awareness. Plain-text output remains suitable for optional TTS; speech is automatic only when explicitly enabled for sharing.

## One-action sharing

Configure the workflow once in the sidebar; use one widget action to run it:

- Text only: approved capture → character reaction.
- Spoken reply: approved capture → character reaction → selected TTS voice.
- Voice question and spoken reply: speech until silence → STT → approved capture → character reaction → TTS.

The main action runs the selected sequence. Desktop either reuses a matching remembered source and approval or opens native setup. The extension receives only advisory approval/source-availability states and cannot read approval records or choose a screen source. Remembered approval is scoped to the instance, account, installation, permission grants, capture kind, and model connection revision; image approval does not authorize video. Changing these or losing the source can require setup again. Older desktop builds retain their original consent flow.

**Stop & Discard** cancels the current capture and persistently pauses this extension's future requests. Use **Allow Screen Capture Requests Again…** in the desktop tray to resume; resuming does not start a capture. **Forget Screen Capture Approvals…** clears saved sources/approvals so the next share asks again. On macOS, remembered displays can survive restart; windows require a live desktop/application session. Windows remembered sources last only while the desktop process and source remain alive.

With voice input enabled, microphone audio goes to the selected STT provider before screen capture; Whistle processes it on the device, while a saved connection sends it to that provider. The **Speech** tab identifies the recognition provider and its processing location. The included question remains available in the speech settings. Once Desktop returns approved media, generation starts automatically, including when approval was remembered.

Both speech options default off. The selected voice is snapshotted when a share starts, and only that request's completed response can trigger TTS once. Partial tokens, other documents, failed/declined captures, or cancelled requests cannot trigger it. Stop disables pending automatic speech for the current share; Cancel/Clear/disposal also abort voice input and speech. STT failure stops before requesting screen capture; TTS failure leaves the generated text intact without retrying paid requests. Starting another share stops old playback before listening, avoiding a TTS-to-STT feedback loop.

Configuration persists per account and synchronizes with reopened widgets. Microphone support depends on the secure browser/native webview and OS/browser microphone consent; unsupported windows can use typed input or the shortcut without voice input. Browser microphone consent is origin-level. Spindle owns microphone capture, silence detection, transcription, and microphone cleanup through `ctx.stt.start({ continuous: false })`. The extension only receives the final transcript and status updates. Choose **Whistle (on this device)** for local recognition without an STT connection or API key, or **STT connection** for a saved profile. Whistle uses Lumiverse's shared model/cache and reports loading progress. Web Speech is also offered when the host supports it; its processing location depends on the browser or device.

All service access routes through Spindle. `ctx.connections.list({ kind: 'tts' | 'stt' })` discovers credential-free speech profiles, `ctx.stt` handles transcription, and `ctx.tts` handles playback. There are no direct HTTP/REST requests or REST fallbacks in extension code. Speech needs the corresponding `speech-to-text-v1`, `text-to-speech-v1`, and `connection-kinds-v1` capabilities and the `media` grant. Older hosts show update guidance while text-only sharing continues. Existing saved settings migrate to the connection provider; voice input and automatic speech remain opt-in.

Version 0.1.10 removes periodic subscription and desktop checks that caused the UI to flash. Actual Spindle connection events restore subscriptions; focus and visibility changes refresh availability without reloading the character catalog or changing connection status. Pending settings edits retain their input debounce during recovery.

Version 0.1.9 saves settings edits after 300 ms without further input. Blur callbacks with unchanged values do not schedule writes, and discovery, state updates, acknowledgements, and closing the panel cannot bypass the debounce. Connection recovery retains pending edits and respects their debounce.

Version 0.1.8 restores the panel subscription after a connection drop, retains pending settings edits while reconnecting, and recovers missing save acknowledgements. Refresh reconnects settings as well as resource discovery. Recovery never replays microphone input, capture, or generation.

Version 0.1.7 adds the shared character picker with thumbnails, full-library search, and scroll loading. It requires the accompanying frontend/backend picker support for these features; older hosts preload pages for local selection. Uses the published `lumiverse-spindle-types` 0.6.71 contract.

Version 0.1.6 uses Spindle types 0.6.69, adds Whistle and Spindle-only speech access, embeds the host's keybinding editors, adds account/document-scoped capture commands, and uses stable desktop IDs and approval discovery. Update the installed extension and reload its frontend. Shortcuts need the accompanying backend routing change and a Desktop build with keybinding support; stable identity and approval discovery need the corresponding native/backend builds. The capture request shape is unchanged.

## Widget startup troubleshooting

Version 0.1.1 fixes a startup gate that incorrectly looked for the backend's `frontend-session-routing-v1` in the frontend descriptor. The frontend provides `frontend-session-origin-v1`; the worker still independently requires server routing. It also retries widget creation when UI Panels is granted after startup, and scopes permission/native-return events to the installation ID rather than the manifest identifier. Widget message IDs use `crypto.getRandomValues`, without requiring the secure-context-only `crypto.randomUUID` API; microphone security requirements are unchanged.

If upgrading from 0.1.0, publish the changed project, update the installed extension, and reload its frontend (or disable/re-enable it and refresh the desktop browser). Rebuilding the backend or the local project alone does not replace the extension bundle installed from its repository. Open the **Desk Companion** drawer tab to see startup status. Native screen-capture enablement controls capture requests, not widget registration. No backend/Tauri rebuild is needed for this extension-only fix.

## Generation request troubleshooting

Version 0.1.3 fixes the raw generation request's missing model/provider fields.
A `connection_id` resolves the stored credentials and endpoint; raw generation
still needs the explicit selected model. Capture-bound generation rejects a
request that does not exactly match the approved model and connection, before
any pixels reach the provider. The extension now supplies both fields from the
owned connection fetched for the share; the host's destination checks are unchanged.

Gemini requests allow a 4,096-token generation budget, including internal reasoning,
while visible replies remain bounded to 4,000 characters and the default prompt
still asks for a concise reaction. Gemini 3 requests use low thinking effort without
displaying thoughts; other routes retain the reasoning-off override. A short text
target is not the same as a thinking-inclusive token budget. This reduces empty
responses caused by consuming a small output budget on reasoning, but does not
guarantee completion for every provider request.

Failures distinguish a changed capture destination, credential/access denial,
quota limits, invalid provider requests, service failures, token-budget exhaustion,
blocked responses, missing terminal completion, and empty text. Raw provider error
bodies, credentials, screen contents, and reasoning are never echoed into widget
state. Failed or incomplete responses do not trigger automatic TTS, and no capture
or paid generation is retried automatically.

Publish/update the installed extension and reload its frontend after upgrading;
rebuilding only the Tauri client or backend does not replace an installed extension
bundle. No backend/Tauri rebuild or Spindle SDK update is required for this fix.

## API integration

| Feature | Implementation |
| --- | --- |
| System floating widgets | `ctx.ui.createFloatWidget`, distinct `setup`/`setupWidget` entries, host-managed pop-out and scoped return handling |
| Desktop capture | Worker-only `spindle.desktop.capture.listDevices`, `getApprovalStatus`, `request`, and `release`; opaque single-use handles never go to the frontend |
| Keyboard shortcuts | `spindle.commands.register/onInvoked/unregister`, authenticated invocation origin, and feature-detected `ctx.components.mountKeybindingEditor` in the settings panel |
| Generation assembly | `assembleMessages` creates provider-neutral messages from the owned character card, user question, and `{ type: 'desktop_capture', asset_id }`; `spindle.generate.rawStream` dispatches them through the exact selected connection |
| Character API | `spindle.characters.list/get` with the trusted frontend sender's user ID; reference fields are bounded and included only in the worker's prompt |
| TTS | `ctx.connections.list({ kind: "tts" })`, `ctx.tts.speak({ text }, { connectionId })`, playback subscription, and `ctx.tts.stop()` in the originating document |
| STT | `ctx.stt.listProviders()`, `ctx.connections.list({ kind: "stt" })`, and `ctx.stt.start({ continuous: false })`; host capture ends on silence and `session.result` supplies the final transcript |

Speech uses the frontend consumer APIs; engine-registration APIs are not consumer routes. Both STT processing and TTS playback require `media`. Screen capture permission does not authorize microphone access. Microphone consent and the explicit share-workflow opt-in remain separate. Connection discovery and provider discovery never request a microphone, load a model, or start speech. TTS is always passed reply text, never a chat message ID, so playback does not write companion replies or audio to chat history.

`spindle.generate.assemble` is also **not** a general-purpose UI prompt builder: it requires an active interceptor's frozen retrieval context. This manual sidecar constructs raw messages explicitly. It does not register interceptors, mutate chats, or run Loom/lorebook/persona retrieval. Selected character description, personality, scenario, examples, and instruction references are included; no normal-chat history is appended.

## Safety and cancellation

- Each observation is user-triggered and names a model/device. There are no background screenshots/listening, automatic retries, rolling buffers, tool calls, filesystem access, computer control, or system-audio capture. Microphone audio is captured only for the explicitly enabled, bounded voice-question step, never attached to the screen recording or sent directly to the text generation model.
- The worker gets user/document identity from `onFrontendMessage`, never from payload fields. Generation responses target the requesting document; synchronized metadata/reply snapshots intentionally reach registered documents for the same authenticated user, each with an exact `frontendSessionId`. Audio is not broadcast. Other users and unsubscribed documents cannot control the shared workflow. State is bounded to 128 accounts, 16 subscribed views per account, and 32 queued state operations per account. One in-flight observation per account, at most eight globally, and a ten-second request cooldown reduce prompt abuse; shortcuts reserve the workflow before opening the microphone. Button input starts synchronously in the user's gesture while the worker confirms the reservation; a rejected reservation immediately cancels that session. Capture and generation always wait for the reservation and completed input. Native host quotas still apply.
- Capture handles are consumed by raw generation and released in `finally`, including cancellation, stale handles, model failure, output limits, and timeout. No capture bytes, IDs, files, leases, or OAuth credentials reach the widget. Errors are fixed messages, not raw provider errors or capture contents. Reasoning tokens are not shown or spoken.
- **Cancel request** aborts an in-flight generation. The current capture request API has no request ID/cancel method or `AbortSignal`. It therefore cannot dismiss an already-open native picker or immediately stop native recording from the worker. Use **Stop & Discard** in the trusted native panel. A cancelled worker waits for that capture to resolve/expire, releases any eventual handle, and never dispatches it to a model. Another observation is blocked until that pending request finishes.
- Closing the originating document, revoking permissions, or unloading the extension aborts worker generation. Native capture also has independent host/device cancellation and expiry. Already released uploads cannot be recalled from a model/STT/TTS provider. Cancelling host STT does not guarantee that processing or billing stops after a remote provider accepts it; local cancellation prevents later screen/model dispatch and playback.
- Replies are capped at 4,000 characters; generation has a 90-second deadline and the capture/generation workflow a four-minute deadline. Voice input normally ends on silence. A 60-second maximum deadline covers input startup, capture, and transcription; it cancels the host session and prevents later capture when speech never finishes. Cancel/Clear/disposal and permission revocation also cancel the session. Host STT owns audio buffers and microphone cleanup; the extension receives no raw audio. The combined typed/spoken question is capped at 1,200 characters. Saved timed-listening preferences are migrated away without changing opt-ins or provider selection. TTS is capped at 2,400 characters and 45 seconds in the extension; host playback owns audio buffers, decoding, and controls. Stop/Clear/disposal stop speech started by this view. Spindle's stop operation stops all host TTS in that document, including chat playback.
- The extension persists only validated, per-user configuration: selected resource IDs, capture/workflow preferences, optional typed direction, and voice settings. It writes no captures, transcripts, replies, audio, or chat messages to storage. Configuration storage is not a secret vault; do not put credentials in the optional direction. The host/model/TTS providers, browser/framework copies, OS paging, and provider-side retention have their own policies. Do not share sensitive screens merely because they can be captured.
- Linux capture and rolling replay buffers remain unavailable. The demo never requests `mode: 'replay'`.

## Live acceptance checklist

- Test screenshot and 1-/30-second video flows in the main document and in a native pop-out. Confirm first-use source selection, optional Remember/Review, exact model destination, no audio, and the correct character voice. Repeat matching shares without another picker; switch image/video and model connection to confirm fresh approval when needed.
- Enable capture with the companion already open, then refocus it; confirm discovery updates without Refresh or starting a capture. Disconnect/reconnect an updated Desktop and confirm the same saved ID becomes ready after refocusing; an older client's new registration must be selected explicitly. Stop & Discard, resume requests, and forget approvals through the tray; confirm advisory status updates after refocusing and no automatic capture/retry. Leave the panel idle and verify it does not flash or resubscribe. Reconnect the host transport and verify settings recover without losing pending edits.
- Configure focused and global shortcuts through the embedded editors. Verify one native global opt-in, conflict reporting, saved bindings after restart, background delivery, no delivery after sign-out/close/disable, and no raw keyboard listener. Invoke both actions with voice input off/on; confirm the quick action never requests the microphone, normal STT failure prevents capture, video settings are honored, and repeat presses do not duplicate capture or speech. Open a second account/window and confirm microphone input runs only in the invoking authenticated document. Test first-use OS microphone permission from a background shortcut on each supported desktop.
- Edit configuration in the sidebar while opening, closing, returning, and reopening native pop-outs. Confirm the compact widget stays scrollable and immediately uses saved settings; reopening never replays paid TTS.
- Open two documents for the same account and a document for another account. Confirm registered views of the same account mirror settings/replies/busy and speech state, only the requester receives audio, and shared cancellation/Stop controls work. Ensure another account or an unsubscribed document receives nothing and cannot cancel the workflow.
- Cancel while waiting for native consent, then discard there; repeat while streaming generation and while synthesizing speech. Close the native source, lock/sleep the desktop, disable native capture, switch instances, revoke grants, and unload the extension. Confirm no delayed model dispatch or speaking.
- Try unsupported models/devices, expired handles, missing character/connection, repeated clicks, oversized replies/audio, provider failures, and autoplay blocking. Render model output such as `<script>` as plain text, never executable markup.
- Test both speech options off/on and the complete one-action flow. Verify no microphone request on widget load, timely track shutdown, cancellation during a pending OS microphone prompt and STT upload, no capture after failed STT, and exactly one TTS request after a completed reaction with one-shot or remembered approval. Check typed-input fallback in each native webview; OS microphone configuration/consent and autoplay are not bypassed.
- Inspect persistence/logs: no extension-written capture files or transcripts, no chat-history writes, no capture-derived provider payload in request history. Check actual GPU encode activity on Windows rather than assuming the acceleration preference proves hardware use.

## Layout

`src/worker.ts` owns the workflow and authorization-bound routing; `src/companion-state.ts` owns per-user persistence, subscriptions, and shared workflow/speech state. `src/settings.ts` validates preferences. `src/prompt.ts` assembles messages. `src/companion-view.ts` renders separate settings and trigger surfaces; `src/companion-widget.ts` registers its bounded host widget. `src/frontend.ts` registers the sidebar configuration; `src/shared-ui.ts` binds its fields and status to host-rendered components; `src/widget.ts` is the lightweight native entry. `src/speech.ts` wraps bounded authenticated TTS requests. `src/speech-input.ts` manages bounded host STT sessions; `src/share-workflow.ts` sequences input and request-bound automatic speech. `tests/` contains non-billable contract/controller and widget lifecycle tests.

- For speech, grant Media and select Whistle with no STT connections configured; verify local model loading, automatic completion after speech and silence, transcription, and both shortcut actions. Check that shorter and longer questions finish on silence rather than a timer, and cancel an indefinitely silent/noisy session with Cancel or the maximum timeout. Test Web Speech on supported hosts. Select a saved STT connection and confirm its explicit ID is honored. Cancel during Whistle loading/processing and verify no later capture. Revoke Media and verify text-only/quick sharing remains possible. For TTS, confirm the selected connection's default voice and Lumiverse speed/volume settings, host playback controls, Stop/Clear, and no duplicate synthesis. Hosts missing the speech APIs must show update guidance without direct REST requests.
